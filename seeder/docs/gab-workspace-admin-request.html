GAB seed — admin unlock + bulk upload

Domain: deccanexperts.us · Part 1 is one-time Google admin work · Part 2 is how we push all 200 from the tool

We need to load Calendar, Gmail, and Drive persona data into the 200 demo mailboxes user1@deccanexperts.us through user200@deccanexperts.us. The operator cannot do this from a normal Google login. A normal login can only write into its own mailbox. Google only allows a bulk write after a Workspace Super Admin turns on domain-wide delegation and sends us one service-account key.

We do not need passwords. We do not need 200 people added to OAuth test users.

Part 1 — Unlock the 200 accounts in Google (you do this once)

What to send back

ItemWhat we need
1. JSON key fileThe service-account key you download in step 2 below (a .json file). Send it privately — Drive restricted link or 1:1 chat. Do not put it in email to a wide list or in git.
2. ConfirmationDomain-wide delegation is saved with the exact scopes below, using this key’s numeric Client ID.
3. Licence checkAll 200 users have a paid Workspace licence that includes Gmail, Calendar, and Drive (not Cloud Identity Free).

Step 1 — Google Cloud project

  1. Open https://console.cloud.google.com and pick the project used for this work (or create one).
  2. APIs & Services → Library. Enable if not already on: Gmail API, Google Calendar API, Google Drive API.

Step 2 — create the service account and download the key

  1. IAM & Admin → Service accounts → + Create service account.
  2. Name it gab-seed. Create and continue. Skip optional roles. Done.
  3. Open gab-seed → Keys → Add key → Create new key → JSON → Create.
  4. Save the downloaded file. Send that file to the operator.
  5. On the same service account, Details tab: copy the numeric Unique ID / Client ID (a long number). Do not use the @….iam.gserviceaccount.com email.

Step 3 — allow that key to act as any @deccanexperts.us user

  1. Open https://admin.google.com as a Super Admin for deccanexperts.us.
  2. Security → Access and data control → API controls → Domain-wide delegation → Manage Domain Wide Delegation → Add new.
  3. Client ID = the numeric ID from step 2.
  4. OAuth scopes = paste this entire line, commas included, with no extra spaces at the ends:
openid,https://www.googleapis.com/auth/userinfo.email,https://www.googleapis.com/auth/gmail.modify,https://www.googleapis.com/auth/calendar,https://www.googleapis.com/auth/drive

Click Authorize.

What this grants

The key may act as any user on deccanexperts.us, only for the APIs in that scope list (identify the user, Gmail modify, Calendar, Drive). Keep the JSON file private. Revoke the Client ID in Domain-wide delegation if the key is leaked.

Step 4 — licences

In Admin console → Directory → Users, confirm user1@deccanexperts.us … user200@deccanexperts.us each have a paid Workspace licence that includes Gmail, Calendar, and Drive.

If admin.google.com does not show Domain-wide delegation, the signed-in account is not a Super Admin. This request has to be done by the person who created the 200 accounts, or they must make the operator a Super Admin.

Part 2 — How to bulk upload from the GAB seed tool

Do this only after Part 1 is finished and you have the JSON key. Nobody clicks Authorize 200 times.

The tool is a local site on the operator’s laptop. It reads the 200-row mapping CSV, matches each row to a persona (Applied ML, Backend, Indie game designer, Student), and writes Calendar / Gmail / Drive into that user’s Google account. Push all matched accounts does the 200 in parallel (4 at a time).

What you need on the laptop

  • The gab-workspace-seed folder (the tool)
  • The service-account JSON key from Part 1 (example path below: /Users/divya/Downloads/gab-sa.json)
  • The 200-row Account mapping CSV (columns used: gmail and Persona loaded)

Step 5 — start the tool in company mode

Stop any old copy of the tool. In Terminal, run this (change the JSON path if the key is saved somewhere else):

export ENV_LOADER_AUTH_BACKEND=workspace_delegation export ENV_LOADER_SA_KEY=/Users/divya/Downloads/gab-sa.json export ENV_LOADER_WORKSPACE_DOMAIN=deccanexperts.us export GAB_PUSH_WORKERS=4 cd /path/to/gab-workspace-seed ./start.sh

Open http://127.0.0.1:8765 and hard-refresh (Cmd+Shift+R). Auth should say workspace_delegation. There is no Authorize button. That is correct.

Step 6 — load all 200, then push

  1. Click Choose CSV and pick the Account mapping sheet (200 rows of userN@deccanexperts.us).
  2. Check the table: each row should show the right email and persona (from Persona loaded). Calendar / Gmail / Drive should already say persona.
  3. Open 05 · Push. Leave Calendar, Gmail, and Drive on. Leave the usual options on (replace previous seed, make Gmail dates recent) unless you were told otherwise.
  4. Click Push all matched accounts. Do not click other buttons while it runs. The page will block them.
  5. Watch the job log. It processes 4 accounts at a time. A red FAIL line is one account/stage that did not land; the rest keep going.

When it is done

Those 200 mailboxes already contain the persona Calendar, Gmail, and Drive data. Annotators sign into Gemini as userN@deccanexperts.us as a populated user. They do not use this tool.

If something is wrong in the tool

What you seeWhat to do
Site still asks to Authorize, or Push all is missingThe tool was started without the four export lines. Stop it and do Step 5 again.
Emails are not @deccanexperts.usWrong CSV, or the sheet’s gmail column was not used. Re-upload the mapping file.
FAIL about domain / not authorized / insufficient permissionPart 1 is incomplete: wrong Client ID, wrong scopes, or the JSON key does not match Domain-wide delegation.
One row failed, others succeededRead the FAIL line (account + stage + error). Fix that user and push that row again. You do not re-do all 200.

Failures also sit on disk in runs/<run-id>/failures.log and jobs/<job-id>.log inside the tool folder. The 200 users cannot see those logs.
